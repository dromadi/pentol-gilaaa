## Tindak lanjut audit operasional (stok di katalog)

Audit kedua (operasional) menemukan katalog bisa menjual melebihi stok dan gagal sinkron tanpa tanda. Sudah diperbaiki:

| Perubahan | Lokasi |
|---|---|
| `pentol_free_stock()` (internal) dan `pentol_catalog_v2()` (publik): `max_qty` diisi hanya saat stok bebas 1–9 pack, jadi jumlah pasti tidak terlihat publik kecuali stok tipis | `admin/security-2026-11.sql` |
| `pentol_submit_checkout` menolak jumlah di atas stok bebas dengan pesan `Stok <nama> tersisa N pack.` (`hint = 'stock'`) | `admin/security-2026-11.sql` |
| Katalog memakai `pentol_catalog_v2`, otomatis kembali ke `pentol_catalog` bila migrasi belum dijalankan | `index.html` `syncCatalog` |
| Label "Sisa N pack" dan tombol + berhenti di batas stok (kartu & keranjang) | `index.html` |
| Banner "Stok dan harga belum berhasil diperbarui" + tombol Coba lagi saat sinkron gagal | `index.html` `#stock-status` |
| Sebelum mencatat pesanan, katalog disinkron ulang; jika harga/stok berubah pembeli dikembalikan ke ringkasan dengan penjelasan | `index.html` submit `#order-form` |
| Bila server menolak karena stok, jumlah di keranjang diturunkan otomatis dan pembeli diminta memeriksa ulang (tidak ada pengalihan ke WhatsApp yang menyesatkan) | `index.html` |

Catatan: permintaan di inbox **tidak** memesan stok. Dua pembeli bisa sama-sama meminta 2 pack terakhir; admin yang menentukan saat memproses. Data Jamur/Lidia HTD tetap harus dibereskan pemilik di admin (masalah data, bukan kode).

Belum dikerjakan (urutan berikutnya): koreksi transaksi, invoice dengan rekening BNI/GoPay, penerimaan barang dari PO, packing per pesanan, laporan per tanggal kejadian, perbaikan visual.

## Cara pengujian yang sudah dilakukan

- Semua SQL dijalankan berurutan di Postgres 16 lokal dengan stub `auth.uid()` dan role `anon`/`authenticated`; `security-2026-11.sql` dijalankan dua kali tanpa error.
- Diuji: anon/authenticated ditolak memanggil fungsi lama; batas per nomor (permintaan ke-9 ditolak); batas global (permintaan ke-41 per jam ditolak); retry `request_id` yang sama tetap sukses.
- Katalog diuji di Chromium (viewport ponsel) dengan Supabase di-mock: label & batas stok tipis, banner gagal + coba lagi, fallback ke `pentol_catalog`, harga berubah sebelum kirim, penolakan stok dari server. Juga di Postgres: `max_qty`, penolakan jumlah berlebih, retry `request_id` lama tetap diterima walau stok sudah habis.
- Admin dibuka di Chromium (Playwright) dengan Supabase di-mock: login, stok, pesanan, dialog invoice, promosi tanpa pelanggaran CSP; skrip inline yang disuntik terblokir.

## Aturan untuk agen berikutnya

- Jangan menjalankan ulang `schema.sql`, `orders.sql`, `operations.sql` di produksi. Perubahan database = file migrasi baru `admin/<topik>-YYYY-MM.sql` yang idempotent (`create or replace`, `if not exists`).
- Domain baru yang dipanggil admin (fetch, font, gambar) harus ditambahkan ke CSP `admin/index.html`.
- Render data pengguna dengan `textContent`, bukan `innerHTML`.
